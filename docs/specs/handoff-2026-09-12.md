## Three traps that cost real time. Do not rediscover them.

1. **A local production build cannot falsify a file-tracing bug.** `next start` resolves from
   `node_modules` and never reads the trace, so the upload path passed every local test while
   production 500'd. Anything depending on a native module must be checked against a deployment.
2. **Next masks every error thrown from a Server Action in production.** A failed upload showed
   only "An error occurred in the Server Components render" plus a digest. The media actions now
   **return** `{ ok, data | error }` instead of throwing. Any new admin action that can fail should
   do the same.
3. **`startTransition` defers the updates inside it.** The upload modal's `setOpen(true)` lived
   inside the form's transition, so it did not paint until the transition finished — i.e. after the
   save it was meant to block. Uploads ran, the save succeeded, and the UI showed nothing. Any form
   that gains a `MediaField` must `await queue.flush()` **outside** `start(...)`.

## Known open items (none blocking)

- **The About page ignores its own media fields.** `about.ts` declares two `image_media_id`s and
  the editor saves them; `about-page.tsx` renders zero media and paints hardcoded Unsplash URLs.
  Staff can upload images there that will never appear. Small fix — the pattern already exists in
  `owners-page.tsx`.
- **One blog cover is broken on the live site.** The seed `media_asset`
  (`00000000-…-0010` → `blog/lisbon-cover.jpg`) has no object in R2, and
  `blog_post.cover_media_id` for `lisbon-str-licensing-2026` points at it. Pre-existing; fixed by
  uploading a real cover.
- **Home's hero secondary CTA still points at `/owners`** — the only owner-facing route left on a
  now guest-facing page. Deliberate for now; flagged for the owner.
- **Orphans are reduced, not eliminated.** A reservation that is never saved leaves nothing, but if
  upload 7 of 10 fails the first six are finalized. D7 is the backstop.
- `scripts/backfill-real-estate-sections.ts` has pre-existing type errors. `scripts/` is outside the
  `pnpm typecheck` gate, so this is latent, not breaking.
