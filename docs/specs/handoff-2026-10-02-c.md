- `contract.ts` grew `getServiceContent`/`listServiceSlugs` (+ the `ServiceContent` shape)
  as the public read for this static content, alongside the existing DB-backed
  `getServiceBySlug`/`listServiceParams` (untouched, still backs the demo seed catalogue for
  other consumers — S9 teaser, S13 sitemap).
- `app/[locale]/services/[slug]/page.tsx` now statically generates exactly those 7 slugs ×
  4 locales from `listServiceSlugs()`; unknown slugs 404. `services-listing.tsx` cards now
  link to the 7 real slugs instead of `href="#"` (Grocery Delivery/Baby-Sitting cards still
  go nowhere — no source content was given for those two).

  path and what it'll take to move it into the backoffice later.
- **Bug fixed same session, before this commit's follow-up**: the enquiry form
  (`leads.ContactForm`) must render **outside** the `.mk` mock wrapper, not inside it —
  `.mk * { margin:0; padding:0 }` (`app/mock.css`) is unlayered CSS and always beats
  Tailwind's layered utility classes regardless of specificity, so nesting the real form
  there silently stripped its input padding/sizing and a hardcoded `color:#fff` heading
  (meant for a dark band that was never actually styled dark) was unreadable. Fixed by
  rendering `EnquireSection` as a sibling after the `.mk` div, built from `core/ui`
  (`Container`/`Section`/`Eyebrow`) the same way `pages/ui/components/lead-cta.tsx` does —
  now visually identical to every other lead form on the site. **If you touch
  `service-detail.tsx` again: never put a live form/client-island inside the `.mk` div.**

**`bccb405` — split the services-index CTA band into image + copy columns:**
- "Planning your stay? Find your apartment, then we'll handle the rest" (bottom of
  `/[locale]/services`) reworked into two columns: a premium apartment photo on the left
  (`photo-1600585154340-be6161a56a0c`, already verified/used elsewhere in the repo), the

## Deferred / known gaps (flagged in README, not fixed here)

- **Service detail content lives in code, not the DB.** `service-detail-content.ts` is
  English-only and hand-authored — no backoffice CRUD, no [T] translation, no per-locale
  slugs. Moving it into the schema (additive migration/ADR) and swapping
  `getServiceContent`/`listServiceSlugs` is the documented next step; `service-detail.tsx`
  itself shouldn't need to change since it already renders from the `ServiceContent` shape.
- **Icon font gap** (pre-existing, unrelated to this session): `service_category.icon` /
  the listing cards' `<i class="iconoir-*">` glyphs render blank — the icon font isn't loaded
  in the app shell yet. The new detail pages deliberately avoid depending on it (inline SVG
  checkmarks instead) rather than inheriting the same gap.
- Grocery Delivery and Baby-Sitting listing cards still link nowhere (`href="#"`) — no source
  content was provided for them this round.
