# Handoff — 2026-10-02 (Owners earnings form → wizard, Buildings parity, FAQ/testimonials polish)

State at `bdf69b2`. Local-only session — nothing deployed. Read this before continuing work on
the Owners page, the Buildings earnings calculator, or the shared `ContactDialog`/testimonials
components; it captures what shipped, what's still open, and two important caveats (DB writes,
no visual QA).

## What changed, by area

**Owners hero (`pages` slice, `owners-page.tsx`):**
- Headline renders one phrase per line (`Your Property` / `Our Expertise` / `Maximum Returns`):
  the content is authored as `"Your Property; Our Expertise; Maximum Returns"` and the render
  splits on `;` → `<br>`. A headline with no `;` still renders as one line — backward compatible.
  Took three passes to land the sizing (font clamp + `white-space:nowrap` + grid column ratio
  `1.1fr .9fr`) — see the CSS comments in that file before touching hero sizing again.
- "Nº of Properties" dropdown → a +/- stepper (new `EstFormStepper` island, min 1, never 0).
  "Nº of Bedrooms" restyled to match it exactly (custom SVG arrow, shared 44px height — the
  native `<select>` chrome was the mismatch, not the CSS) and extended to `Studio…6+`.
- The whole earnings-estimate form is now a **3-step wizard** (new `EstFormWizard` island,
  `[data-wizard]`/`[data-panel]`/`[data-wiz-next|back]`): property details → contact details
  (name, email, phone **with country-code select**, 2 consent checkboxes) → confirmation.
  **Purely client-side navigation — nothing submits anywhere yet** (explicit, per the user).
- Removed the "Free and with no obligation." note under the form (DB content, `earnings_form.note`
  cleared on the live row + seed).
- New "Contact Us" button under the hero copy opens the **same shared `ContactDialog`** as the
  header's envelope icon (not a copy). See the cross-cutting `ContactDialog` section below —
  this is the one change in this session with the widest blast radius.
- Plan cards (Core/Prime/Manage/Complete) got a circular corner-badge with a percentage (10% /
  14% / +5% / +9%) — new optional `tier.corner_badge` field, local to `owners.ts`'s schema.
- "Your growth path" — the 5 step cards are now photo-backgrounds with a dark gradient scrim
  (Pexels placeholders, swap for real R2 assets later). New `journeyStep` schema = shared `step`
  **extended locally** with `image_media_id` — deliberately did *not* add the image field to the
  shared `_shared.ts` `step` (Real Estate also uses that shape and didn't ask for images).
- Closing CTA ("Ready to Make Your Property Work for You?") is now two columns — photo left,
  the existing copy/CTA/contact line right (was single centered column). `OWNERS_BODY_BOTTOM`
  (a const string) became `ownersBodyBottom()` (a function) to build the `<img>` tag.

**Shared `ContactDialog` (`settings` slice) — now exported via `contract.ts`:**
- Added an optional `source` prop (defaults to the existing `"header-contact"`, so the header's
  own usage is unchanged) and a `light` variant (white hairline, for dark hero media).
- **The dialog/backdrop now portals to `document.body`**, always, regardless of caller. This
  was a real bug fix, not a style choice: when `<ContactDialog>` is rendered from inside a page
  that uses the `.mk` mock-CSS scope (Owners, Buildings), the modal — if left in-place — inherits
  that page's `.mk *{margin:0;padding:0}` reset and heading/type rules, visibly breaking its
  Tailwind styling (padding stripped, wrong font treatment). Portaling to `body` makes the modal
  identical everywhere it's used. No behavior change for the header's own usage beyond "now a
  child of `<body>` instead of the header" (harmless).
- `EstFormStepper` and `EstFormWizard` (the Owners wizard's behavior, no page coupling) are now
  **exported from `pages/contract.ts`** so other slices can reuse the exact same component instead
  of re-implementing it — Buildings does, below.

**Buildings (`buildings` slice):**
- Index page (`buildings-listing.tsx`) hero gets the same "Contact Us" → `ContactDialog` pattern
  as Owners. Could **not** import the Owners `HeroContactCta` portal helper directly (cross-slice
  rule — it isn't on `pages/contract.ts`, and it's trivial enough not to warrant adding it there);
  `src/slices/buildings/ui/components/hero-contact-cta.tsx` is a deliberate duplicate — same file,
  same comment explaining why, in both slices.
- `buildings.viewMore` ("View more") → **"View All Units"** in all 4 locales — static next-intl
  UI string, not backoffice-editable (confirmed and explained to the user: that's expected).
- The earnings-calculator section ("★ Earn +25% / Discover your property's earning potential")
  was the *old* single-column form design (plain `<select>`s, one button) — now replaced with the
  **exact same 3-step wizard** as the Owners hero (same markup/CSS classes, real behavior reused
  via the new `pages/contract.ts` exports), laid out in two columns: form left, photo right.
- Building-detail page (`building-detail.tsx`): the gallery+spec-strip band ("6 APARTMENTS / 25
  GUESTS / 12 BEDS / neighbourhood") now sits flush under the hero (new `.specband{padding:0}`
  class) and pulls whatever section follows 15% of `--section-y` closer via a negative
  `margin-bottom` on the band itself (robust to which section follows — that varies per building).
- **Apartment cards now show an icon spec row** (bedrooms/beds/guests/size in m²) instead of a
  plain-text meta line — 4 new line-icon SVGs, page-scoped CSS (`.pspecs`/`.pspec`), the shared
  kernel `.pmeta` used by the *building* cards on the index page is untouched.
- Buildings vs Real Estate hero height mismatch (measured 659px vs 491px by the user): Real
  Estate's hero was missing the `style="padding:0"` every other `.hero.compact` page carries
  (fixed), and Buildings' hero paragraph was ~2x longer than Real Estate's (shortened to a
  comparable length instead of fighting it with a `max-width` override — tried that first, a
  62ch override wasn't nearly enough and was reverted). Not pixel-verified (see QA caveat below).

**Apartments (`apartments` slice) — editability + seed data:**
- `size_m2` was **dropped from the admin editor** in an earlier, deliberate simplification
  ("apartments have no standalone page, keep the editor minimal") — restored it (validation
  schema, save action, form field) because the new card display needs it. `bathrooms`/`floor`
  are still dropped from the editor on purpose; only `size_m2` came back.
- **The `apartment` table was completely empty** (0 rows) before this session — the demo seed
  script only ever wrote the *buildings'* denormalized stats, never actual unit rows, so "Apartments
  in this Building" was empty on every building. Seeded 34 published units across the 6 demo
  buildings (guests/beds per unit sum to each building's existing stats — `scripts/seed-demo.ts`
  now does this on a fresh seed too, via a new `seedApartmentsFor` helper + `splitEven`).

**Testimonials marquee (`pages` slice, shared Home/Owners component):**
- Owner-audience cards get a subtle warm tint (`bg-accent/5` + `border-accent/25`, same pattern
  used elsewhere for active/status chips) vs the plain `bg-surface` Guest cards — visible where
  both audiences mix in one carousel (Owners; Home no longer renders this section at all, per
  ADR 0031, so the contrast isn't visible there).

**FAQ sections (`pages` slice, 5 pages: Home/Owners/Guest/Real Estate/About):**
- Removed the small red "FAQ" eyebrow label above every FAQ section's heading (`FaqSection`'s
  `eyebrow` prop dropped, all 5 call sites updated, the now-orphaned `faqEyebrow` key removed
  from all 4 locale files). Section titles themselves are unchanged.

## ⚠️ Database: this session wrote to the live Neon DB directly, repeatedly

Same instance flagged in the 2026-09-28 handoff — **still not confirmed whether it's production
or dev/staging; treat it as production.** Every direct write this session used a throwaway
`scripts/_tmp-*.ts` file (deleted immediately after running, never committed), bypassing the
app's own publish/revalidate path, same pattern as last time:

- Patched the live `owners` `page_content` row directly several times: hero headline text,
  `earnings_form.note` removal, `journey.steps[].image_media_id`, `plans.tiers[].corner_badge`.
- Seeded 34 `apartment` rows (see above) — additive, nothing deleted or overwritten.

After each direct write, `.next/dev/cache/fetch-cache` was deleted and the dev server restarted
to bust `unstable_cache` (harmless in `next dev`; **if this DB is ever read by a deployed/ISR
build, those rows' tags — `page:owners`, `apartment-list` — need an explicit revalidate**, they
were never hit through `revalidateTag`/`revalidatePath`).

## ⚠️ No visual/browser QA this session either

Same constraint as last handoff — no screenshot/browser automation tool was available. Every
change was verified via `curl` against `pnpm dev` + grepping the rendered HTML/served CSS, not
by looking at it. This matters most for:
- The Owners 3-step wizard's actual click-through feel (dots progress, back/next, mobile).
- The Buildings/Real Estate hero height match — fixed by reasoning about padding + paragraph
  length from one user-reported measurement (659px vs 491px), not re-measured after the fix.
- The new apartment-card icon spec row and photo-background growth-path cards at small widths.

**A real look in a browser (desktop + ~390px mobile) is worth doing before calling any of this
shippable**, especially the wizard and the two hero-height fixes.
