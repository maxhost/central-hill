# SEO / GEO + i18n implementation rules

> "GEO/GEM" = Generative Engine Optimization: being accurately citable by AI search/LLM answer
> engines, in addition to classic SEO. Both are won by the same fundamentals — clean,
> server-rendered, well-structured, fast, multilingual HTML — not by any hosting vendor.
> Owned by slice **S13 · seo-geo**; every public slice supplies its URLs + structured data.

## Locales & URLs
- Locales: `en | pt | es | fr`, **all path-prefixed**: `/{locale}/...`.
- `/` (root) redirects via `Accept-Language`/geo, default `en`. No un-prefixed content URLs.
- **Per-locale slugs** for every public entity (`slug` table, unique per `(entity_type, locale)`).
- Public URL patterns (localizable slugs; examples in EN):
  - `/{locale}/buildings` · `/{locale}/buildings/{building-slug}`
  - `/{locale}/buildings/{building-slug}/{apartment-slug}` (or `/{locale}/apartments/{slug}`)
  - `/{locale}/blog` · `/{locale}/blog/{post-slug}` (+ category filter)
  - `/{locale}/services` · `/{locale}/services/{service-slug}`
  - `/{locale}/guides/{city-slug}` · `/{locale}/guides/{city-slug}/{page-slug}`
  - marketing: `/{locale}`, `/{locale}/owners`, `/{locale}/real-estate`, `/{locale}/about`, `/{locale}/guests`

## hreflang & canonical
- Every public page emits `<link rel="alternate" hreflang="...">` for all 4 locales **plus**
  `x-default` → the root redirector. Canonical = the page's own localized URL.
- Alternates are generated from the per-locale slug table so they always resolve to the right
  translated slug, not a naive locale swap.

## Metadata
- Per-entity `meta_title` / `meta_description` are translatable fields. Fallback chain:
  entity meta → entity name/excerpt → page default. Build via `core/seo` `buildMetadata()`.
- Open Graph + Twitter cards per page, with an R2-served OG image (entity cover or branded default).

## Structured data (JSON-LD) — emit per page type
- **Organization** + **LocalBusiness** (site-wide, from `globals`: name, logo, address, phones, social).
- **Apartment**/**Product**/**LodgingBusiness** for apartment pages (name, photos, amenities,
  numberOfRooms, occupancy, address, containedInPlace → Building).
- **BlogPosting** for posts (headline, author, datePublished, image, articleBody summary).
- **FAQPage** for FAQ groups and any page with Q&A.
- **BreadcrumbList** for catalog/blog hierarchy.
- Use builders in `core/seo`; never hand-write JSON-LD in components.

## GEO (generative engine) specifics
- Serve fully-rendered HTML (RSC/ISR) — no client-only content that an LLM crawler can't see.
- Maintain **`/llms.txt`** (and `/llms-full.txt`) describing the site, key sections, and canonical
  URLs to help AI engines cite Central Hill accurately. Generated by S13 from the slice catalog.
- Clean semantic headings (one `h1`/page), descriptive link text, factual consistent NAP
  (name/address/phone) matching the LocalBusiness JSON-LD.
- Stable, descriptive, localized URLs; avoid query-param-only states for indexable content.

## Sitemaps & robots
- Per-locale XML sitemaps, split per entity type, with `<xhtml:link>` alternates. Sitemap index at
  `/sitemap.xml`. Regenerated on publish (tag `sitemap`). `robots.txt` allows all public, disallows
  `/backoffice`, references the sitemap.

## Performance budget (SEO + UX)
- Targets: LCP < 2.5s (aim ~200ms TTFB via CDN static), CLS < 0.1, INP < 200ms.
- Public JS shipped per route kept minimal (RSC-first; client islands only where needed).
- Images: AVIF/WebP, responsive `srcset`, lazy below the fold, explicit dimensions.
- Third-party (Avantio) loaded lazily/post-interaction; fonts `font-display: swap`, preloaded subset.
- CI Lighthouse budget gate on representative public routes.

## Content translation gating
- Public pages render only **`approved`** translations; if a locale field is `missing`/`draft`,
  fall back to the source locale and (optionally) mark the alternate as not-yet-translated to avoid
  emitting hreflang for a non-existent translation. Policy configurable in `core/i18n/config`.
